# С2000-Ethernet: Modbus RTU поверх UDP — полное описание транспорта

> **Назначение документа.** Самодостаточное описание того, как система КВТ-С опрашивает
> преобразователь протокола **С2000-ПП** (Болид) через преобразователь интерфейсов
> **С2000-Ethernet**, работающий в прозрачном режиме. Документ можно передать сторонней команде
> или ИИ-ассистенту, чтобы добавить режим «С2000-Ethernet» в программу, которая уже умеет
> Modbus RTU через COM-порт.
>
> Всё, что помечено «(проверено)», взято из работающего кода (`poller/modbus_client.py`) и
> подтверждено реальным обменом с прибором. Всё, что помечено «(на стороне прибора)»,
> настраивается в утилите **UProg** и должно быть сверено с эксплуатационной документацией
> Болид на конкретную ревизию прибора.
>
> Спецификация подсистемы опроса — [§3 Modbus Poller](../03-specification/03-poller.md),
> формальное описание обёртки — [§3.2.1](../03-specification/03-poller.md).

## 1. Общая картина

### 1.1 Цепочка передачи данных

```
Датчики С2000-ВТ
      │  ДПЛС (двухпроводная линия связи)
      ▼
С2000-КДЛ  (или С2000-КДЛ-Modbus)
      │  RS-485, внутренний протокол «Орион» (Болид)
      ▼
С2000-ПП   ← преобразователь протокола: Орион → ВЕДОМЫЙ Modbus RTU
      │  RS-485 (Modbus RTU)
      ▼
С2000-Ethernet  ← прозрачный «мост» RS-485 ⇄ Ethernet (UDP)
      │  Ethernet / UDP
      ▼
Программа (Modbus RTU МАСТЕР)
```

**Ключевая мысль:** С2000-Ethernet **не является** Modbus TCP шлюзом. Он работает как
«удлинитель COM-порта» — прозрачно переносит байты RS-485 через UDP. Поэтому:

* **НЕ используется** Modbus TCP (нет MBAP-заголовка, нет transaction id);
* **используется** обычный **Modbus RTU кадр вместе с CRC16**, помещённый в UDP-датаграмму;
* прибор ведёт себя как синхронный последовательный канал: **один запрос → один ответ**.

### 1.2 Два варианта UDP-транспорта

Система поддерживает два режима, потому что разные ревизии/настройки С2000-Ethernet ведут
себя по-разному:

| Режим (`transport`) | Что в UDP-датаграмме | Когда применять |
|---|---|---|
| `udp_rtu` | **Чистый** Modbus RTU кадр + CRC16, без каких-либо добавок | «Честный» прозрачный режим: прибор переносит байты 1:1 |
| `udp_c2000pp` | Modbus RTU кадр + CRC16, завёрнутый в **5-байтовую служебную обёртку** | Наблюдаемое поведение С2000-Ethernet в связке с С2000-ПП: прибор добавляет собственный служебный заголовок |

> **Практика (проверено):** на реальном объекте работает `udp_c2000pp` — прибор добавляет
> 5-байтовый заголовок и к запросам, и к ответам. Режим `udp_rtu` оставлен для установок,
> где обёртки нет. **Рекомендация:** реализовать оба и сделать выбор параметром линии;
> при пусконаладке определить фактический режим по дампу первой ответной датаграммы
> (см. §7 «Как определить режим»).

## 2. Формат обёртки `udp_c2000pp` (преамбула)

### 2.1 Байтовая структура

```
 байт:   0        1        2    3        4        5 ... 5+LEN-1
       +--------+--------+---------+--------+===========================+
       | prefix |  LEN   |   SEQ   |channel |  Modbus RTU frame (LEN)   |
       |  0x10  | 1 байт | 2 байта |  0x10  |   вместе с CRC16          |
       +--------+--------+---------+--------+===========================+
       └────────────── 5 байт заголовка ────┘└──── полезная нагрузка ───┘

 Полная длина UDP-датаграммы = 5 + LEN
```

### 2.2 Поля заголовка

| Поле | Смещение | Размер | Значение по умолчанию | Порядок байт | Описание |
|---|---|---|---|---|---|
| `prefix` | 0 | 1 байт | `0x10` | — | Маркер начала пакета. Настраиваемый параметр линии |
| `LEN` | 1 | 1 байт | вычисляется | — | Длина **вложенного RTU-кадра** (без 5 байт заголовка). Максимум 255 |
| `SEQ` | 2–3 | 2 байта | старт `0x21D1` | **big-endian** (старший байт первым) | Счётчик датаграмм отправителя |
| `channel` | 4 | 1 байт | `0x10` | — | Канал/адрес преобразователя. Настраиваемый параметр линии |
| `payload` | 5 | `LEN` байт | — | как в RTU | Готовый Modbus RTU кадр **вместе с CRC16** |

### 2.3 Критично важные правила по SEQ (проверено)

1. **TX SEQ** — свой счётчик на каждую линию опроса. Инкремент **+1 на каждый запрос**,
   переполнение по модулю `0x10000` (`seq = (seq + 1) & 0xFFFF`).
2. **RX SEQ — НЕ эхо запроса!** Прибор ведёт **собственный независимый счётчик** ответных
   датаграмм. Значения TX SEQ и RX SEQ **не совпадают и не должны сравниваться**.
   RX SEQ следует только **логировать** для диагностики.
   > Это главная ловушка: попытка сопоставить ответ по SEQ приведёт к тому, что все ответы
   > будут отброшены как «чужие».
3. **Сопоставление запроса и ответа** выполняется **не по SEQ**, а по вложенному
   Modbus RTU кадру: `slave_id`, `function` (или `function | 0x80` для исключения),
   длина, корректность CRC16.
4. `seq_start` — начальное значение (по умолчанию `0x21D1`); `seq_persist` — сохранять ли
   текущее значение между перезапусками (значение отдаётся в статусе линии как `seq_current`).

### 2.4 CRC16 не меняется

Обёртка **не заменяет и не пересчитывает** Modbus CRC16. Внутри `payload` лежит точно тот же
кадр, который был бы отправлен в COM-порт. После снятия заголовка CRC проверяется тем же кодом,
что и для RS-485.

## 3. Полная таблица параметров линии

```jsonc
{
  "id": "pp_udp_1",                 // уникальный идентификатор линии
  "name": "UDP-192.168.66.100",     // человекочитаемое имя (стабильное)
  "enabled": true,
  "transport": "udp_c2000pp",       // "serial" | "udp_rtu" | "udp_c2000pp"

  // --- сетевые параметры ---
  "remote_host": "192.168.66.100",  // IP преобразователя С2000-Ethernet (ОБЯЗАТЕЛЬНО)
  "remote_port": 40005,             // UDP-порт прибора (1..65535)
  "local_host": "192.168.66.97",    // локальный IP для bind (важно! см. §3.1)
  "local_port": 40005,              // локальный UDP-порт для bind (0 = любой)

  // --- обёртка udp_c2000pp ---
  "prefix": "0x10",                 // байт 0 обёртки (0..255)
  "channel": "0x10",                // байт 4 обёртки (0..255)
  "seq_start": "0x21D1",            // начальный TX SEQ (0..65535)
  "seq_persist": true,              // сохранять SEQ между перезапусками

  // --- Modbus ---
  "device_slave_id": 16,            // Slave ID С2000-ПП (0..247; 0 = брать из датчика)
  "timeout_ms": 500,                // таймаут ожидания ответа (50..10000)

  // --- параметры опроса (пер-линейные; 0/-1 = использовать общие) ---
  "poll_period_ms": 0,              // период опроса линии (0 = общий; иначе >=100)
  "retry_count": -1,                // повторов до «медленного цикла» (-1 = общий; 0..10)
  "slow_poll_period_ms": 30000      // период «медленного цикла» (1000..3600000)
}
```

Общие (глобальные) параметры опроса:

| Параметр | По умолчанию | Диапазон | Назначение |
|---|---|---|---|
| `poll_period_ms` | 1000 | 100–60000 | Период цикла опроса |
| `timeout_ms` | 500 | 50–10000 | Таймаут ожидания ответа |
| `retry_count` | 3 | 0–10 | Повторов запроса к датчику |
| `value_register_base` | 30000 | 0–65535 | База регистров значений |
| `status_register_base` | 40000 | 0–65535 | База регистров статусов |

### 3.1 Важно: bind локального порта

Штатная схема (проверено): ПК `192.168.66.97:40005` ⇄ прибор `192.168.66.100:40005`.

Многие ревизии С2000-Ethernet в прозрачном режиме отправляют ответ **на конкретный
порт-адресат**, заданный в настройках прибора, а не на порт-источник запроса. Поэтому:

* сокет **обязательно** нужно биндить на `local_host:local_port`;
* `local_port` обычно **совпадает** с `remote_port` (симметричная пара портов);
* если не забиндиться — запросы уйдут, а ответы придут «в никуда» и будут выглядеть как таймаут.

> Если `local_host` не задан — биндиться на `0.0.0.0` (все интерфейсы) с указанным портом.
> В системе КВТ-С локальный IP определяется автоматически и подставляется в интерфейсе
> (кнопка «Определить»), чтобы оператор не вводил его вручную.

### 3.2 Порты: наблюдаемые значения

| Установка | UDP-порт |
|---|---|
| Данный проект (КВТ-С) | `40005` (симметрично: локальный = удалённый) |
| Другой объект (проект СМВТ) | `41200` |

Порт **не стандартизован** — он задаётся в настройках самого прибора (UProg) и должен
совпадать в конфигурации программы. **Не хардкодить.**

## 4. CRC16 Modbus (проверено)

Стандартный Modbus CRC-16: полином `0xA001` (реверсивный от `0x8005`), начальное значение
`0xFFFF`, **в кадр записывается младшим байтом вперёд (little-endian)**.

```python
def crc16_modbus(data: bytes) -> int:
    crc = 0xFFFF
    for byte in data:
        crc ^= byte
        for _ in range(8):
            if crc & 0x0001:
                crc = (crc >> 1) ^ 0xA001
            else:
                crc >>= 1
    return crc

# добавление в кадр: сначала младший байт, затем старший
tx_frame = request + bytes([crc & 0xFF, (crc >> 8) & 0xFF])

# проверка принятого кадра:
crc_received   = rx_frame[-2] | (rx_frame[-1] << 8)
crc_calculated = crc16_modbus(rx_frame[:-2])
```

## 5. Алгоритм обмена (пошагово)

### 5.1 Открытие линии

```
1. Создать UDP-сокет (AF_INET, SOCK_DGRAM).
2. Установить таймаут = timeout_ms / 1000 секунд.
3. ЕСЛИ задан local_host ИЛИ local_port:
       bind( (local_host или "0.0.0.0", local_port) )
4. Инициализировать TX SEQ = seq_current (если сохранён) иначе seq_start.
```

UDP не имеет соединения, поэтому «открытие» — это только создание и bind сокета.

### 5.2 Один запрос-ответ

```
1. Сформировать Modbus RTU кадр (PDU + CRC16) — точно как для COM-порта:
       [slave_id][function][addr_hi][addr_lo][count_hi][count_lo][crc_lo][crc_hi]

2. ОЧИСТИТЬ сокет от протухших датаграмм (drain):
       перевести сокет в неблокирующий режим и вычитывать recvfrom()
       до BlockingIOError/timeout; посчитать сколько выброшено (в лог).
       ← КРИТИЧНО: без этого рассинхронизация «запрос N ↔ ответ N-1» после
         любого таймаута сохраняется навсегда.

3. ЕСЛИ transport == udp_c2000pp:
       seq = TX_SEQ
       datagram = [prefix][len(rtu)][seq_hi][seq_lo][channel] + rtu
       TX_SEQ = (TX_SEQ + 1) & 0xFFFF
   ИНАЧЕ (udp_rtu):
       datagram = rtu

4. sendto(datagram, (remote_host, remote_port))

5. recvfrom(2048)  — ждать не дольше timeout_ms
       при таймауте → ошибка «нет ответа», обычная логика повторов

6. ЕСЛИ transport == udp_c2000pp:
       проверить len(datagram) >= 5              иначе invalid_udp_wrapper
       проверить datagram[0] == prefix            иначе invalid_udp_wrapper
       проверить datagram[4] == channel           иначе invalid_udp_wrapper
       RX_SEQ = (datagram[2] << 8) | datagram[3]  → только в лог, НЕ сравнивать
       payload = datagram[5:]
       проверить datagram[1] == len(payload)      иначе invalid_udp_wrapper
       rtu_response = payload
   ИНАЧЕ:
       rtu_response = datagram

7. Разобрать rtu_response тем же кодом, что и для COM-порта (см. §5.3).
```

### 5.3 Валидация ответного RTU-кадра (общая для COM и UDP)

Проверки выполняются строго в этом порядке:

| № | Проверка | Ошибка при несоблюдении |
|---|---|---|
| 1 | `len(rx) >= 5` | `Incomplete response: got=N, expected>=5` |
| 2 | `rx[1] & 0x80` — бит исключения | `Modbus exception: slave=S, function=F, code=rx[2]` |
| 3 | `len(rx) == 3 + rx[2] + 2` | `Incomplete response: got=N, expected=M` |
| 4 | `rx[0] == slave_id` и `rx[1] == function` | `Unexpected response header` |
| 5 | CRC16 совпадает | `CRC error: got=XXXX, expected=YYYY` |
| 6 | `rx[2] == count * 2` | `Unexpected byte count` |

Извлечение значений:

```python
payload   = rx_frame[3:-2]
registers = [int.from_bytes(payload[i:i+2], "big") for i in range(0, len(payload), 2)]
```

Регистры — **16 бит big-endian** (старший байт первым).

### 5.4 Предварительные проверки запроса

```
1 <= slave_id <= 247          иначе "Invalid slave id"
0 <= start_addr <= 0xFFFF     иначе "Invalid register address"
1 <= count <= 125             иначе "Invalid register count"
len(rtu) <= 255               иначе "RTU frame too long for UDP wrapper"
```

Ограничение 255 — из-за однобайтового поля `LEN` в обёртке.

## 6. Реальные примеры байтов (проверено, сгенерировано кодом)

### 6.1 Чтение 2 регистров (температура + влажность)

```
Параметры: slave_id=1, function=0x03, start_addr=30000 (0x7530), count=2, SEQ=0x21D1

RTU-кадр (то, что ушло бы в COM-порт):
    01 03 75 30 00 02 DE 08                                     (8 байт)
    │  │  └──┬──┘ └──┬──┘ └──┬──┘
    │  │     addr   count   CRC16 (мл. байт первым)
    │  функция 0x03 (Read Holding Registers) — именно её использует опрос
    slave id

UDP-датаграмма udp_c2000pp (то, что реально уходит в сеть):
    10 08 21 D1 10 | 01 03 75 30 00 02 DE 08                   (13 байт)
    │  │  └──┬──┘ │   └──────────── RTU (8 байт) ──────────┘
    │  │   SEQ    channel=0x10
    │  LEN=8 (0x08)
    prefix=0x10
```

> **Важно про функцию:** цикл опроса КВТ-С читает **и значения, и статусы функцией 0x03**
> (Read Holding Registers) — см. `poller/modbus_client.py: read_holding_registers_raw`.
> Функция 0x04 (Read Input Registers) в клиенте реализована, но в опросе не используется.
> При переносе в другую программу ориентируйтесь на фактическую настройку таблицы Modbus
> в вашем С2000-ПП (UProg) и проверяйте обе функции на этапе пусконаладки.

### 6.2 Ответ прибора

```
UDP-датаграмма от прибора (SEQ прибора СВОЙ, например 0x0A57):
    10 09 0A 57 10 | 01 03 04 19 80 37 00 EA B7                (14 байт)
    │  │  └──┬──┘ │   └──────────── RTU (9 байт) ──────────┘
    │  │  RX SEQ=0x0A57 ← только логировать! НЕ сравнивать с 0x21D1
    │  LEN=9
    prefix

RTU-кадр после снятия обёртки:
    01 03 04 19 80 37 00 EA B7                                  (9 байт)
    │  │  │  └──┬──┘ └──┬──┘ └──┬──┘
    │  │  │   рег.1   рег.2   CRC16
    │  │  byte_count = 4 (2 регистра × 2 байта)
    │  функция (эхо)
    slave id (эхо)

Регистры: [0x1980, 0x3700] = [6528, 14080]
Пересчёт Q8.8 (знаковое / 256): температура 6528/256 = 25.5 °C, влажность 14080/256 = 55.0 %
```

### 6.3 Modbus-исключение

```
UDP:  10 05 0A 58 10 | 01 83 02 C0 F1
RTU:  01 83 02 C0 F1
      │  │  │
      │  │  код исключения 0x02 (Illegal Data Address)
      │  0x83 = 0x03 | 0x80 → бит исключения установлен
      slave id
```

### 6.4 Сканирование устройства (поиск Slave ID)

```
Запрос чтения 1 регистра по адресу status_register_base (40000 = 0x9C40),
функция 0x03, slave_id=16 (0x10):

RTU:  10 03 9C 40 00 01 A8 CF
UDP:  10 08 00 01 10 | 10 03 9C 40 00 01 A8 CF
                        ▲▲ slave_id=0x10 — не путать с prefix/channel!

Есть валидный ответ → устройство найдено. Нет ответа → не найдено.
```

> Обратите внимание: `slave_id = 16 = 0x10` численно совпадает с `prefix` и `channel`.
> При отладке дампов это путает — ориентируйтесь на смещения байт, а не на значения.

## 7. Как определить фактический режим (`udp_rtu` или `udp_c2000pp`)

При пусконаладке на незнакомом объекте:

1. Отправить запрос **без обёртки** (`udp_rtu`) и снять дамп ответной датаграммы.
2. Посмотреть первый байт и общую длину:
   * ответ начинается сразу с `slave_id` и длина = ожидаемой длине RTU → режим **`udp_rtu`**;
   * ответ начинается с `0x10`, длина = RTU + 5, байт[4] = `0x10`, байт[1] = длина остатка →
     режим **`udp_c2000pp`**.
3. В логах системы для этого предусмотрены отдельные поля: полная датаграмма
   (`tx_transport_frame` / `rx_transport_frame`) и «чистый» RTU (`tx_frame` / `rx_frame`) —
   рекомендуем сделать так же, иначе отладка обёртки практически невозможна.

Диагностическая ошибка `invalid_udp_wrapper` означает: включён режим `udp_c2000pp`, но пришёл
кадр, не соответствующий обёртке (в т.ч. чистый RTU) — вероятно, нужно переключиться на `udp_rtu`.

## 8. Референсная реализация (Python, самодостаточная)

Копируемый минимум, повторяющий проверенную логику. Без внешних зависимостей.
Проверено: формирование/разбор кадров **побайтово совпадает** с рабочим кодом
`poller/modbus_client.py`.

```python
import socket
import time


def crc16_modbus(data: bytes) -> int:
    crc = 0xFFFF
    for b in data:
        crc ^= b
        for _ in range(8):
            crc = (crc >> 1) ^ 0xA001 if crc & 1 else crc >> 1
    return crc


class C2000EthernetModbus:
    """Modbus RTU мастер поверх UDP через С2000-Ethernet.

    mode: 'udp_c2000pp' — с 5-байтовой обёрткой; 'udp_rtu' — чистый RTU в UDP.
    """

    def __init__(self, remote_host, remote_port=40005,
                 local_host="", local_port=0,
                 mode="udp_c2000pp", timeout_ms=500,
                 prefix=0x10, channel=0x10, seq_start=0x21D1):
        self.remote = (remote_host, int(remote_port))
        self.local_host, self.local_port = local_host, int(local_port or 0)
        self.mode, self.timeout = mode, float(timeout_ms) / 1000.0
        self.prefix, self.channel = prefix & 0xFF, channel & 0xFF
        self.seq = seq_start & 0xFFFF
        self.rx_seq = None            # последний SEQ прибора (только для лога)
        self.sock = None

    # ---------- жизненный цикл ----------
    def open(self):
        self.close()
        self.sock = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
        self.sock.settimeout(self.timeout)
        if self.local_host or self.local_port:
            # КРИТИЧНО: прибор часто отвечает на фиксированный порт
            self.sock.bind((self.local_host or "0.0.0.0", self.local_port))
        return True

    def close(self):
        if self.sock:
            try:
                self.sock.close()
            except OSError:
                pass
        self.sock = None

    # ---------- обёртка ----------
    def _wrap(self, rtu: bytes, seq: int) -> bytes:
        if len(rtu) > 255:
            raise ValueError(f"RTU frame too long for UDP wrapper: {len(rtu)}")
        return bytes([self.prefix, len(rtu),
                      (seq >> 8) & 0xFF, seq & 0xFF,
                      self.channel]) + rtu

    def _unwrap(self, dg: bytes) -> bytes:
        if len(dg) < 5:
            raise IOError("invalid_udp_wrapper: shorter than 5-byte header")
        if dg[0] != self.prefix or dg[4] != self.channel:
            raise IOError(f"invalid_udp_wrapper: prefix/channel mismatch {dg[:5].hex(' ')}")
        self.rx_seq = (dg[2] << 8) | dg[3]        # НЕ сравнивать с self.seq!
        payload = dg[5:]
        if dg[1] != len(payload):
            raise IOError(f"invalid_udp_wrapper: LEN={dg[1]}, payload={len(payload)}")
        return payload

    def _drain(self) -> int:
        """Выбросить протухшие датаграммы. Обязательно перед каждым запросом."""
        n, old = 0, self.sock.gettimeout()
        try:
            self.sock.settimeout(0.0)
            while True:
                try:
                    self.sock.recvfrom(2048)
                    n += 1
                except (BlockingIOError, socket.timeout, OSError):
                    break
        finally:
            self.sock.settimeout(old)
        return n

    # ---------- обмен ----------
    def read_registers(self, slave_id, start_addr, count, function=0x03):
        """function: 0x03 Read Holding Registers (используется опросом КВТ-С),
        0x04 Read Input Registers (поддерживается, но в опросе не применяется)."""
        if not self.sock:
            raise IOError("not connected")
        if not 1 <= slave_id <= 247:
            raise ValueError(f"Invalid slave id: {slave_id}")
        if not 0 <= start_addr <= 0xFFFF:
            raise ValueError(f"Invalid register address: {start_addr}")
        if not 1 <= count <= 125:
            raise ValueError(f"Invalid register count: {count}")

        pdu = bytes([slave_id, function,
                     (start_addr >> 8) & 0xFF, start_addr & 0xFF,
                     (count >> 8) & 0xFF, count & 0xFF])
        crc = crc16_modbus(pdu)
        tx = pdu + bytes([crc & 0xFF, (crc >> 8) & 0xFF])   # CRC little-endian

        t0 = time.perf_counter()
        self._drain()

        if self.mode == "udp_c2000pp":
            dg = self._wrap(tx, self.seq)
            self.seq = (self.seq + 1) & 0xFFFF              # инкремент по модулю 0x10000
        else:
            dg = tx

        self.sock.sendto(dg, self.remote)
        raw, _peer = self.sock.recvfrom(2048)               # socket.timeout → нет ответа
        elapsed_ms = round((time.perf_counter() - t0) * 1000, 2)

        rx = self._unwrap(raw) if self.mode == "udp_c2000pp" else raw

        # --- валидация RTU (тот же код, что для COM-порта) ---
        if len(rx) < 5:
            raise IOError(f"Incomplete response: got={len(rx)}, expected>=5")
        if rx[1] & 0x80:
            raise IOError(f"Modbus exception: slave={slave_id}, "
                          f"function={function}, code={rx[2]}")
        if len(rx) != 3 + rx[2] + 2:
            raise IOError(f"Incomplete response: got={len(rx)}, expected={3 + rx[2] + 2}")
        if rx[0] != slave_id or rx[1] != function:
            raise IOError(f"Unexpected response header: {rx[:2].hex(' ')}")
        if (rx[-2] | (rx[-1] << 8)) != crc16_modbus(rx[:-2]):
            raise IOError("CRC error")
        if rx[2] != count * 2:
            raise IOError(f"Unexpected byte count: got={rx[2]}, expected={count * 2}")

        body = rx[3:-2]
        regs = [int.from_bytes(body[i:i + 2], "big") for i in range(0, len(body), 2)]
        return {
            "registers": regs,
            "response_time_ms": elapsed_ms,
            "tx_datagram": dg, "rx_datagram": raw,   # для лога: полные датаграммы
            "tx_rtu": tx, "rx_rtu": rx,              # для лога: чистый RTU
            "tx_seq": (self.seq - 1) & 0xFFFF, "rx_seq": self.rx_seq,
        }


# ------------------------- пример использования -------------------------
def signed_16(v):
    """Сырое 16-битное -> знаковое."""
    return v if v < 32768 else v - 65536


def q8_8(v):
    """Формат С2000-ВТ: знаковое 16-битное / 256 (fixed point Q8.8)."""
    return signed_16(v) / 256.0


if __name__ == "__main__":
    dev = C2000EthernetModbus(
        remote_host="192.168.66.100", remote_port=40005,
        local_host="192.168.66.97",  local_port=40005,   # симметричная пара портов
        mode="udp_c2000pp", timeout_ms=500,
    )
    dev.open()
    try:
        # функция 0x03 (Read Holding Registers) — как в опросе КВТ-С
        r = dev.read_registers(slave_id=1, start_addr=30000, count=2, function=0x03)
        print("TX:", r["tx_datagram"].hex(" ").upper())
        print("RX:", r["rx_datagram"].hex(" ").upper())
        print("registers:", r["registers"],
              "| t=", round(q8_8(r["registers"][0]), 4), "°C",
              "| h=", round(q8_8(r["registers"][1]), 4), "%")
        print("tx_seq=%04X rx_seq=%04X (не сравниваются)" % (r["tx_seq"], r["rx_seq"]))
    finally:
        dev.close()
```

## 9. Прикладной уровень: карта регистров С2000-ПП

Транспорт не зависит от карты регистров, но для полноты (как настроено в данной системе):

| Группа | База (настраиваемая) | Содержимое |
|---|---|---|
| Значения | `value_register_base` = **30000** | Измеренные величины датчиков |
| Статусы | `status_register_base` = **40000** | Состояние датчиков/зон |

* Функция чтения: **0x03** (Read Holding Registers) — и для значений, и для статусов
  (`poller/modbus_client.py: read_holding_registers_raw`). Функция 0x04 реализована в клиенте,
  но в цикле опроса не применяется. Фактическая функция зависит от настройки таблицы Modbus
  в С2000-ПП (UProg) — проверять при пусконаладке.
* Один датчик С2000-ВТ занимает **2 адреса**: температура и влажность (читаются одним запросом
  `count=2`).
* **Пересчёт — формат Q8.8 (fixed point):**

  ```python
  def signed_16(v):            # сначала знаковое 16-битное
      return v if v < 32768 else v - 65536

  value = signed_16(raw) / 256.0   # затем деление на 256
  ```

  Примеры: `0x1980 = 6528 → 25.5 °C`; `0x3700 = 14080 → 55.0 %`;
  отрицательная температура `0xF380 → signed −3200 → −12.5 °C`.
  Округление в системе — до 4 знаков.
* Максимум **256 датчиков** на один С2000-ПП.
* Адрес зоны/датчика в таблице Modbus С2000-ПП **задаётся в UProg** — соответствие
  «зона ↔ регистр» нужно сверять с настройкой конкретного прибора.

> Точная карта регистров и способ адресации зон **настраиваются в UProg** и различаются между
> ревизиями С2000-ПП. Транспортная часть (§2–§8) от этого не зависит.

## 10. Настройка на стороне приборов (на стороне прибора, сверять с UProg)

Программа не конфигурирует приборы — она только читает готовые данные. Перед опросом
в утилите **UProg** (Болид) должно быть настроено:

**С2000-КДЛ (контроллер ДПЛС)**
* адреса датчиков С2000-ВТ на ДПЛС;
* параметры линии связи.

**С2000-ПП (преобразователь протокола)**
* Slave ID (адрес Modbus, 1–247) — в программе это `device_slave_id`;
* параметры RS-485 (скорость, чётность) — должны совпадать с С2000-Ethernet;
* таблица зон → регистров Modbus (какая зона в каком регистре).

**С2000-Ethernet (преобразователь интерфейсов)**
* **прозрачный режим** (transparent / «удлинитель COM») — НЕ Modbus TCP шлюз;
* IP-адрес, маска, шлюз — в программе это `remote_host`;
* UDP-порт — в программе это `remote_port` (наблюдались `40005` и `41200`);
* IP и порт партнёра (адресата) — должны указывать на компьютер с программой; именно поэтому
  локальный сокет нужно биндить на `local_host:local_port`;
* параметры RS-485 — идентично С2000-ПП.

> Каждый С2000-Ethernet — отдельный IP в ЛВС, то есть **одна линия опроса = один прибор**.
> Для нескольких С2000-ПП делается несколько независимых линий (у каждой свой сокет,
> свой TX SEQ, своя статистика).

## 11. Подводные камни (собрано по опыту эксплуатации)

| № | Проблема | Причина и решение |
|---|---|---|
| 1 | Все ответы отбрасываются как «чужие» | Попытка сопоставить ответ по SEQ. **RX SEQ — независимый счётчик прибора**, сопоставлять нужно по вложенному RTU (slave/function/длина/CRC) |
| 2 | Запросы уходят, ответов нет (постоянный таймаут) | Не выполнен `bind` на `local_host:local_port`, либо порт не совпадает с настройкой прибора в UProg |
| 3 | После одного таймаута всё «съезжает» на один ответ | Не выполняется **drain** сокета перед запросом: приходит ответ на предыдущий запрос. Обязательно чистить сокет |
| 4 | `invalid_udp_wrapper` на каждом ответе | Прибор работает без обёртки — переключить режим на `udp_rtu` |
| 5 | Ответ приходит, но CRC error | Обёртка снята неверно (лишние/недостающие байты). Проверить: `LEN == len(payload)`, заголовок ровно 5 байт |
| 6 | Путаница при чтении дампов | `slave_id = 16 = 0x10` численно совпадает с `prefix`/`channel`. Ориентироваться на смещения байт |
| 7 | Работает на одном объекте, не работает на другом | Порт (`40005` vs `41200`) и режим обёртки различаются между установками. Всё делать параметрами, не хардкодить |
| 8 | Один «мёртвый» датчик тормозит весь опрос | Таймауты × повторы × число датчиков. Решение: «медленный цикл» — датчик, исчерпавший повторы, опрашивается раз в `slow_poll_period_ms` (одна попытка), но не выпадает из опроса и возвращается автоматически при первом ответе |
| 9 | Опрос останавливается при сетевом сбое | Цикл опроса должен быть полностью защищён от исключений (любая ошибка → лог + продолжение) + watchdog, перезапускающий упавший поток линии |
| 10 | Не видно, что реально в сети | Логировать **и** полную датаграмму (с обёрткой), **и** чистый RTU, плюс `tx_seq`/`rx_seq`, время ответа, число выброшенных при drain |

## 12. Чек-лист внедрения в существующую Modbus-программу

Если программа уже умеет Modbus RTU через COM-порт, добавление режима С2000-Ethernet
сводится к **подмене транспортного слоя** — формирование и разбор RTU-кадра остаются теми же.

- [ ] 1. Ввести параметр линии `transport`: `serial` | `udp_rtu` | `udp_c2000pp`.
- [ ] 2. Добавить сетевые параметры: `remote_host`, `remote_port`, `local_host`, `local_port`.
- [ ] 3. Добавить параметры обёртки: `prefix` (0x10), `channel` (0x10), `seq_start` (0x21D1), `seq_persist`.
- [ ] 4. В функции открытия линии: для UDP-режимов создать сокет, задать таймаут, **сделать bind**.
- [ ] 5. Вынести обмен в отдельный метод `_exchange_frame(rtu) → rtu_response`, где вся разница между COM и UDP.
- [ ] 6. Для `udp_c2000pp`: реализовать `_wrap` (+инкремент TX SEQ) и `_unwrap` (+проверки prefix/channel/LEN, чтение RX SEQ в лог).
- [ ] 7. Реализовать **drain** сокета перед каждым запросом.
- [ ] 8. Оставить валидацию RTU-ответа и CRC16 **без изменений** — она общая.
- [ ] 9. Расширить журнал обмена полями: полная датаграмма TX/RX, `tx_seq`, `rx_seq`, `remote`, число выброшенных датаграмм, время ответа.
- [ ] 10. Проверку `len(rtu) <= 255` (ограничение поля LEN).
- [ ] 11. Отдельный экземпляр транспорта (сокет + TX SEQ) **на каждую линию**; линии опрашивать независимыми потоками, чтобы таймаут одного прибора не задерживал остальные.
- [ ] 12. Пусконаладка: снять дамп первого ответа и определить фактический режим (§7).

## 13. Сводка «золотых правил»

1. Это **Modbus RTU (с CRC16) внутри UDP**, а не Modbus TCP.
2. Обёртка `udp_c2000pp` = **5 байт**: `0x10 | LEN | SEQ(2, big-endian) | 0x10`.
3. `LEN` — длина **только** вложенного RTU-кадра; полная датаграмма = `5 + LEN`.
4. **TX SEQ** инкрементируется на каждый запрос по модулю `0x10000`.
5. **RX SEQ прибора независим** — только логировать, **никогда** не сравнивать.
6. Сопоставление ответа — по **вложенному RTU**: slave, function/`|0x80`, длина, CRC16.
7. **Bind** локального сокета обязателен; `local_port` обычно = `remote_port`.
8. **Drain** сокета перед каждым запросом — иначе рассинхронизация после таймаута.
9. CRC16 обёрткой **не затрагивается**; в кадре CRC идёт **младшим байтом вперёд**.
10. Регистры — **16 бит big-endian**; физическая величина = **знаковое 16-битное / 256** (Q8.8),
    а не `/10`. Функция чтения в опросе — **0x03**.
11. Один С2000-Ethernet = одна линия = свой сокет и свой TX SEQ.
12. Порт и наличие обёртки **различаются между объектами** — только параметры, без хардкода.
