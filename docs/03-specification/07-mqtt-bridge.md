# 7. Подсистема 5: MQTT Bridge

## 7.1 Назначение

MQTT Bridge — двунаправленный мост между системой КВТ и MQTT-брокером. Обеспечивает:

- **публикацию** текущих данных датчиков в топики брокера (для внешних систем: SCADA, IoT-платформы,
  Home Assistant, шлюзы верхнего уровня);
- **приём** входящих MQTT-сообщений (внешние значения датчиков и команды управления).

Подсистема не опрашивает оборудование: источником данных является тот же нормализованный текущий
срез, что отдаёт Web Visualizer через `/api/current` (модуль `shared/current_data.py`).

Технологическая база:

- сервис: `mqtt_bridge`;
- запуск: `python -m mqtt_bridge.app`;
- библиотека: `paho-mqtt==2.1.0`;
- порт брокера по умолчанию: `1883`;
- статус сервиса: `data/mqtt_status.json`;
- журнал входящих сообщений: `data/mqtt_inbound.json`.

## 7.2 Конфигурация MQTT (mqtt_config.json)

`data/config/mqtt_config.json` — единственный источник настроек MQTT. Конфиг входит в полный
ZIP-архив переноса настроек.

```json
{
  "enabled": false,
  "autostart": false,
  "broker": {
    "host": "0.0.0.0",
    "port": 1883,
    "keepalive_seconds": 60,
    "client_id": "kvt-c-mqtt",
    "username": ""
  },
  "topics": {
    "base": "kvt-c"
  },
  "publishing": {
    "enabled": true,
    "interval_ms": 1000,
    "qos": 0,
    "retain": true,
    "publish_snapshot": true,
    "publish_per_sensor": true
  },
  "receiving": {
    "enabled": true,
    "qos": 0
  },
  "tls": {
    "enabled": false,
    "ca_cert_path": "",
    "client_cert_path": "",
    "client_key_path": "",
    "insecure": false
  }
}
```

| Поле | По умолчанию | Диапазон / правила | Назначение |
|------|--------------|--------------------|------------|
| `enabled` | `false` | — | Главный выключатель публикации/приёма |
| `autostart` | `false` | — | Поднимать ли сервис при `run_kvt.py start --service all` |
| `broker.host` | `0.0.0.0` | self-адреса разрешаются в актуальный IP машины | Адрес MQTT-брокера |
| `broker.port` | `1883` | 1–65535 | Порт брокера |
| `broker.keepalive_seconds` | `60` | 5–3600 | MQTT keepalive |
| `broker.client_id` | `kvt-c-mqtt` | — | Идентификатор клиента |
| `broker.username` | `""` | — | Логин; пароль хранится отдельно и маскируется в API |
| `topics.base` | `kvt-c` | без пробелов и wildcard `#`/`+` | Базовый префикс всех топиков |
| `publishing.enabled` | `true` | — | Публиковать ли данные наружу |
| `publishing.interval_ms` | `1000` | 250–60000 | Период публикации |
| `publishing.qos` | `0` | 0–2 | QoS публикации |
| `publishing.retain` | `true` | — | Флаг retain для публикуемых сообщений |
| `publishing.publish_snapshot` | `true` | — | Публиковать общий срез в один топик |
| `publishing.publish_per_sensor` | `true` | — | Публиковать каждый датчик в свой топик |
| `receiving.enabled` | `true` | — | Принимать ли входящие сообщения и команды |
| `receiving.qos` | `0` | 0–2 | QoS подписок |
| `tls.enabled` | `false` | — | Включение TLS |
| `tls.ca_cert_path` | `""` | — | CA-сертификат |
| `tls.client_cert_path` | `""` | требует `client_key_path` | Клиентский сертификат |
| `tls.client_key_path` | `""` | требует `client_cert_path` | Клиентский ключ |
| `tls.insecure` | `false` | — | Не проверять имя хоста в сертификате |

Правила:

- `enabled=false` — процесс может быть запущен, но обмен с брокером не ведётся;
- смена `broker.*` и `tls.*` применяется при переподключении; изменения `publishing`/`receiving`
  и состава топиков сервис перечитывает автоматически;
- self-адреса (`0.0.0.0`, `localhost`, пустой host) разрешаются в актуальный IP машины через
  `shared/net.py` — жёсткий петлевой адрес в конфигурации не используется;
- пароль брокера хранится вне основного конфига и маскируется при выдаче через REST API.

## 7.3 Карта топиков

Все топики строятся от `topics.base` (по умолчанию `kvt-c`). Базовый префикс нормализуется:
убираются ведущие/замыкающие `/` и дублирующиеся разделители.

| Направление | Топик | Назначение |
|-------------|-------|------------|
| Публикация | `{base}/status` | Состояние сервиса MQTT Bridge |
| Публикация | `{base}/current` | Полный текущий срез всех датчиков (снимок) |
| Публикация | `{base}/sensors/{id}` | Значения отдельного датчика (по его ID) |
| Подписка | `{base}/inbound/sensors/+` | Приём внешних значений датчиков (wildcard по ID) |
| Подписка | `{base}/commands/republish` | Команда: немедленно опубликовать срез заново |
| Подписка | `{base}/commands/ping` | Команда: проверка связи, обновление статуса |

Формат полезной нагрузки — **JSON в кодировке UTF-8** (компактный, без лишних пробелов,
`ensure_ascii=false`, поэтому русские строки читаемы «как есть»).

## 7.4 Публикация данных

- Публикация выполняется периодически с интервалом `publishing.interval_ms`.
- При `publish_snapshot=true` в топик `{base}/current` уходит полный нормализованный срез —
  тот же состав датчиков и те же fallback-значения, что отдаёт `/api/current`.
- При `publish_per_sensor=true` каждый датчик дополнительно публикуется в собственный топик
  `{base}/sensors/{id}`, что позволяет внешним системам подписываться выборочно.
- В топик `{base}/status` публикуется состояние сервиса (то же, что пишется в
  `data/mqtt_status.json`): состояние подключения, активные топики, время обновления, ошибка.
- Флаги `qos` и `retain` применяются ко всем публикуемым сообщениям.

## 7.5 Приём входящих сообщений и команды

При `receiving.enabled=true` сервис подписывается на топики из таблицы 7.3:

- **Внешние значения датчиков** (`{base}/inbound/sensors/+`) — принятые сообщения складываются в
  журнал `data/mqtt_inbound.json` (с ограничением числа хранимых записей) и доступны через
  REST API `/api/mqtt/inbound` для просмотра оператором. Приём входящих значений не подменяет
  данные опроса Modbus.
- **Команда `republish`** — сервис немедленно публикует срез, не дожидаясь очередного интервала.
- **Команда `ping`** — сервис обновляет статус, подтверждая живость связи с брокером.

## 7.6 Настройки и API

Страница `/settings/mqtt` в Web Visualizer позволяет оператору:

- включить/выключить обмен и автозапуск сервиса;
- задать адрес, порт, keepalive, client_id, имя пользователя и пароль брокера;
- задать базовый топик;
- настроить публикацию: интервал, QoS, retain, публикация среза и/или по датчикам;
- настроить приём: включение и QoS;
- настроить TLS: пути к CA/сертификату/ключу, флаг `insecure`;
- видеть состояние сервиса, активные топики и журнал входящих сообщений.

API Web Visualizer:

| Метод | Endpoint | Описание |
|-------|----------|----------|
| GET | `/api/mqtt/config` | Получить `mqtt_config.json` (пароль маскируется) |
| POST | `/api/mqtt/config` | Провалидировать и сохранить настройки MQTT |
| GET | `/api/mqtt/status` | Получить `data/mqtt_status.json` (состояние, подключение, топики) |
| GET | `/api/mqtt/inbound` | Получить журнал входящих MQTT-сообщений |
| POST | `/api/mqtt/reload` | Сообщить сервису о необходимости перечитать конфигурацию |

## 7.7 Запуск

`run_kvt.py` — единая точка запуска:

```bash
python run_kvt.py start --service mqtt
python run_kvt.py status
python run_kvt.py restart --service mqtt
python run_kvt.py stop --service mqtt
```

При `--service all` сервис `mqtt` поднимается **только при включённом `autostart`** (как и OPC UA);
ручной запуск `--service mqtt` доступен всегда. Логи: `logs/mqtt.out.log`, `logs/mqtt.err.log`;
PID-файл: `.run/mqtt.pid`.

## 7.8 Критерии приёмки

- `python run_kvt.py --help` содержит `mqtt` в списке сервисов; `status` показывает состояние
  сервиса и признак `autostart`.
- `/settings/mqtt` сохраняет все настройки без потери ввода; пароль не возвращается в открытом виде.
- `/api/mqtt/config` и `/api/mqtt/status` возвращают JSON.
- При `enabled=true` и доступном брокере внешний MQTT-клиент видит сообщения в топиках
  `{base}/current` и `{base}/sensors/{id}`, а также состояние в `{base}/status`.
- Публикация ведётся с заданным интервалом; состав датчиков и fallback-значения совпадают с
  `/api/current`.
- Публикация в `{base}/commands/republish` вызывает немедленную повторную публикацию среза.
- Сообщения, отправленные в `{base}/inbound/sensors/{id}`, появляются в `/api/mqtt/inbound`.
- При недоступном брокере сервис не завершается: состояние отражается в
  `data/mqtt_status.json`, попытки подключения повторяются.
