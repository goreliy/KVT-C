## 14.2 Таски для параллельного опроса и опроса по эзернету

| ID | Задача | Результат | Приоритет |
|----|--------|-----------|-----------|
| M1 | Ввести модель `poll_ports[]` в `poller_config.json` | Конфиг хранит несколько линий; старые поля мигрируют в линию `default` | Высокий |
| M2 | Обновить валидацию poller config | Проверяются уникальность `id/name`, диапазоны UDP/COM, обязательные поля по типу транспорта | Высокий |
| M3 | Реализовать транспорт `udp_c2000pp` | RTU-кадр заворачивается в `10 LEN SEQ_hi SEQ_lo 10`, ответ распаковывается без сравнения RX SEQ с TX SEQ; валидность проверяется по вложенному Modbus RTU | Высокий |
| M4 | Добавить bind локального UDP endpoint | Поддержана схема ПК `192.168.66.97:40005` -> прибор `192.168.66.100:40005` | Высокий |
| M5 | Реализовать `PollPortManager` и workers линий | Каждый COM/UDP порт опрашивается независимо; manager агрегирует статус, current и log | Высокий |
| M6 | Привязать датчики к `poll_port_id` | Опросчик группирует датчики по линии; offline одной линии не влияет на остальные | Высокий |
| M7 | Добавить `local_number` и `display_number` | UI показывает номер вида `COM8-001` или `UDP-192.168.66.100-001` | Высокий |
| M8 | Обновить `current.json` | В payload есть `poll_ports[]`, транспортные поля датчика и статистика по линиям | Высокий |
| M9 | Расширить `modbus_log.json` | Для UDP пишутся чистые RTU `tx_hex/rx_hex` и полные `wrapped_tx_hex/wrapped_rx_hex` | Высокий |
| M10 | Обновить scan | Поиск выполняется на выбранной линии `poll_port_id`; результат содержит transport/endpoint | Средний |
| M11 | Обновить Poller service page | Статус и лог показывают линии, SEQ, endpoint, ошибки и последние обмены | Средний |
| M12 | Покрыть транспорт тестами | Тесты CRC, упаковки, независимого RX SEQ, LEN, очистки протухших датаграмм, CRC после распаковки | Высокий |
| M13 | Добавить управление одной линией через API | Start/stop/restart/log/scan работают для выбранного `poll_port_id` без остановки остальных | Высокий |
